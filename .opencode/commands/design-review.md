# /design-review

请按 design-orchestrator 的标准工作流完成以下设计需求，**使用 review 模式**。

**用户需求**：$ARGUMENTS

**Mode**: `review`

要求：
1. 严格按 Step 0 → Step 0.5 → **Step 1a（生成问卷）** → **Step 1b（用户选择偏好）** → **Step 1c（基于偏好规划）** → Step 2 → Step 3 → Step 4 → Step 5 顺序执行
2. **Step 1a 必须执行**：调 planner mode=options 让它自主生成 5-8 个动态问卷选项
3. **Step 1b 必须执行**：用 markdown 表格渲染问卷，等待用户回复
4. 在用户回复"全部默认 / OK / 具体选择"前不要进入 Step 1c
5. 用户选择必须作为硬约束级联到 wbs 与下游 designer prompt
6. 全部产物落盘到 `artifacts/<slug>/` 目录
7. 最终给用户简洁的 Markdown 汇总，含 Critique 总分与产物索引链接

---

**模式说明**（来自系统设计哲学）：
- `/design`（auto 模式）—— 全自动一气呵成，约 20 分钟出整套设计
- `/design-review`（本模式）—— **planner 主动出题**让用户在关键偏好上选择，偏好硬约束到下游执行，约 25-35 分钟（含用户答题时间）

review 模式的真正价值是**主动暴露选择空间**，而不是被动让用户挑错。AI 自己识别"哪些决策一旦错就全套作废"，把这些维度做成结构化问卷，给用户：
1. **明确选项**（不是模糊讨论） —— 单选 / 多选 / 数值
2. **每项默认值** —— 一句"全部默认"快速通过
3. **风险等级标注** —— 致命 / 重要 / 微调，用户优先关注高风险项
4. **AI 推荐理由** —— 让用户判断要不要采纳

适合在以下情况使用：
- 这是关键品牌（不能有方向性错误）
- 心中有偏好但没想过如何表达（让 AI 帮你拆解维度）
- 想看 AI 自动决定但保留否决权（最常见用法）
- 答辩 / 演示场景（展示 AI 决策过程的透明度 + 人机协同能力）
